# Плагин MAX для Hermes Agent

Плагин подключает профиль Hermes Gateway к чат-боту MAX. Он принимает события через webhook и отправляет ответы Hermes через Bot API MAX.

## Что поддерживается

- Личные сообщения, групповые чаты и каналы.
- Текст в Markdown, файлы, индикатор набора текста в группах и каналах.
- Кнопки для выбора модели, подтверждений, уточняющих вопросов и других поддерживаемых интерактивных сценариев Hermes.
- Команды бота MAX: в нативном меню помещается до 32 команд; остальные доступны через `/commands` и ручной ввод.
- Доставка cron-задач в `MAX_HOME_CHANNEL`.

## Требования

- Верифицированный профиль организации, ИП или самозанятого на платформе MAX.
- Чат-бот MAX со статусом `created` после модерации.
- Токен бота из MAX Partner Platform.
- Публичный HTTPS URL с доверенным сертификатом. MAX должен иметь возможность отправлять запросы на этот URL.
- Разрешенные идентификаторы пользователей в `MAX_ALLOWED_USERS`.

Плагин не создает и не модерирует ботов MAX, не выпускает TLS-сертификаты и не настраивает туннель, reverse proxy или Kubernetes.

## Установка

Установите плагин из GitHub:

```bash
hermes plugins install https://github.com/Deezzir/max-platform
```

Для именованного профиля добавьте `-p <профиль>`. Плагин работает внутри среды Python, установленной вместе с Hermes.

Включите платформу в `config.yaml` профиля:

```yaml
gateway:
  platforms:
    max:
      enabled: true
```

Секреты укажите в `.env` профиля, а не в `config.yaml`:

```env
MAX_BOT_TOKEN=...
MAX_WEBHOOK_URL=https://bot.example.ru/
MAX_WEBHOOK_SECRET=...
MAX_ALLOWED_USERS=123456789,987654321
```

Обязательные переменные:

| Переменная | Назначение |
| --- | --- |
| `MAX_BOT_TOKEN` | Токен Bot API MAX. |
| `MAX_WEBHOOK_URL` | Публичный HTTPS URL, который регистрируется в MAX. |
| `MAX_WEBHOOK_SECRET` | Секрет для заголовка `X-Max-Bot-Api-Secret`. |
| `MAX_ALLOWED_USERS` | Разрешенные MAX user ID через запятую. |

Необязательные переменные:

| Переменная | Назначение |
| --- | --- |
| `MAX_LISTEN_HOST` | Адрес локального listener, по умолчанию `0.0.0.0`. |
| `MAX_LISTEN_PORT` | Локальный порт listener, по умолчанию `8080`. |
| `MAX_HOME_CHANNEL` | ID чата или канала для доставки cron-задач. |
| `MAX_REQUIRE_MENTION` | Если `true`, в группах и каналах бот отвечает только на сообщения с `@bot_username`. На личные сообщения не влияет. |

## Webhook и развертывание

Плагин слушает:

- `POST /` для webhook MAX.
- `GET /health` для проверки состояния.

Инфраструктура должна перенаправлять публичный HTTPS URL на локальный порт плагина. Например:

```text
MAX -> public HTTPS -> reverse proxy/tunnel -> сервис -> Hermes:MAX_LISTEN_PORT
```

Включите доступ бота к групповым чатам в настройках MAX, если бот должен работать в группах или каналах.

## Группы и упоминания

В группе ответ отправляется в тот же групповой чат, а не в личные сообщения пользователя.

При `MAX_REQUIRE_MENTION=true` используйте:

```text
@имя_бота /model
@имя_бота помоги с задачей
```

Упоминание бота удаляется перед обработкой команды Hermes. Поэтому `@имя_бота /model` запускает обычную команду `/model`.

## Кнопки и команды

MAX поддерживает inline-кнопки. Плагин использует их для выбора модели, выбора вариантов, уточняющих вопросов и подтверждений. Кнопки доступны только пользователям из `MAX_ALLOWED_USERS`.

Выбор модели показывает до 8 моделей на странице и кнопки `Previous`, `Next`, `Back` и `Close`. `Close` отменяет выбор и убирает кнопки.

MAX позволяет зарегистрировать до 32 команд в меню бота. MAX не предоставляет автодополнение при наборе `/`, поэтому команды можно выбирать из меню бота, вводить вручную или просматривать через `/commands`.

## Проверка работы

После запуска Hermes проверьте:

```bash
curl http://127.0.0.1:8080/health
```

Ожидаемый ответ:

```json
{"status": "ok", "platform": "max"}
```

Проверьте логи Hermes: должны появиться сообщения о запуске listener, регистрации webhook и подключении адаптера MAX.

## Ротация токена

1. Выпустите новый токен в MAX Partner Platform.
2. Обновите `MAX_BOT_TOKEN` в окружении профиля Hermes.
3. Перезапустите Gateway.
4. Убедитесь, что webhook и `/health` работают.

Ошибка MAX `401` означает проблему конфигурации токена и не повторяется автоматически.

## Разработка

Для проверки изменений запустите:

```bash
tox
```

Не добавляйте в репозиторий токены, webhook-секреты, личные данные пользователей или конфигурацию развертывания.
